## 2. 严重问题：LaTeX 导入反编译有损

当前入口：`crates/mathslot-core/src/latex.rs:823` 的 `latex_to_mathslot`。

它不是完整的 LaTeX 解析器，而是 `convert_latex_chars`（`latex.rs:878`）的字符串重写器。部分结构可以正确往返，但上下标和矩阵这类依赖“原子 + 脚本”的结构会被破坏。

### 2.0 用户给出的示例复现

输入：

```latex
\int_{-\infty}^{\infty} {e}^{-x^{2}} \mathrm{d}x = \sqrt{\pi}
```

实际生成：

```text
▸i-oo;oo;e^-x^2 dx;= ▸r▸gp;
```

实际反推：

```latex
\int_{-\infty}^{\infty} e^{-x}^{2} \,\mathrm{d}x= \sqrt{\pi}
```

结论：

- `e^{-x^{2}}` 被拆成 `e^{-x}^{2}`，指数分组丢失；
- `= ` 两侧空格在往返后丢失（次要）；
- 积分主体 `e^-x^2 dx` 没有结构化上下标，导航看不到指数槽；
- 这个例子同时命中 2.1 的脚本问题和 2.4 的文本空格问题。

### 2.1 上下标分组丢失（P0）

实际运行结果：

| 输入 LaTeX | 生成简码 | 反推 LaTeX | 问题 |
| :--- | :--- | :--- | :--- |
| `e^{-x^{2}}` | `e^-x^2` | `e^{-x}^{2}` | 外层指数分组丢失，`-x` 成为指数，`2` 变成第二个上标 |
| `x^{a+b}` | `x^a+b` | `x^{a}+b` | 指数只取了 `a`，`+b` 掉到外面 |
| `a_{i+1}` | `a_i+1` | `a_{i}+1` | 下标只取了 `i`，`+1` 掉到外面 |
| `e^{-\frac{x}{2}}` | `e^-▸fx;2;` | `e^{-} \frac{x}{2}` | 指数为空，`\frac` 被移出指数 |

根因链：

1. `convert_latex_chars` 的通用 `{...}` 分支只保留内部字符串，**剥掉花括号**；
2. 遇到 `^` / `_` 时没有生成 MathSlot 的 `▸u` / `▸d` / `▸b` 结构，而是原样输出 `^` / `_` 文本；
3. 导出时 `latex_range`（`latex.rs:223`）再用 `latex_operand`（`latex.rs:374`）重新解释 `^` / `_`；
4. `latex_operand` 对未加花括号的参数只取一个“原子”，所以 `-x` 被当成完整指数，后面的 `^2` 变成新的上标。

这不是单个正则问题，而是**同一份上下标语义存在两套表示**：`▸u/▸d/▸b` 结构表示，以及文本里的 `^/_` 原始表示。导入器生成后者，导出器又用启发式解释后者，必然出现有损。

### 2.2 `\left` 被误判为关系符，导致求和/积分后空槽（P0）

实际运行：

```latex
\sum_{i=1}^{n} \left( a_i \right)
```

生成：

```text
▸si=1;n;;▸p a_i ;
```

反推：

```latex
\sum_{i=1}^{n} \left(a_{i}\right)
```

求和主体槽 `▸s` 的第三个槽是空的，`\left(...\right)` 跑到了求和外面。积分同理：

```latex
\int_a^b \left( f(x) \right) dx
```

生成：

```text
▸ia;b;;▸p f(x) ; dx
```

根因在 `extract_term_body`（`latex.rs:1237`）：

```rust
let rest: String = chars[i..].iter().take(8).collect();
if rest.starts_with("\\le")
    || rest.starts_with("\\ge")
    ...
```

`\left` 的前三个字符是 `\le`，所以 `rest.starts_with("\\le")` 为真，主体提取在这里提前结束。

这是一个典型的“关系宏前缀匹配”错误：

- `\left` 被当成 `\le`
- `\leftrightarrow` 也可能被 `\le` / `\left` 干扰
- `\ge` 与 `\geq`、`\ne` 与 `\neq` 需要按完整宏名判断

修复方向：解析 `\` 后的完整宏名字，精确匹配 `le/leq/ge/geq/ne/neq/approx/equiv/sim`，而不是 `starts_with`。

### 2.3 矩阵环境不支持（P1）

输入：

```latex
\begin{pmatrix} a & b \\ c & d \end{pmatrix}
```

当前输出：

```text
\beginpmatrix a & b \\ c & d \endpmatrix
```

反推：

```latex
\beginpmatrix a \& b \\ c \& d \endpmatrix
```

问题：

- `\begin{pmatrix}` / `\end{pmatrix}` 没有被识别为矩阵结构；
- `&` 在普通文本转换中被转义为 `\&`；
- 没有生成 `▸ma` / `▸mb` / 自定义 Env 格式；
- 导航和槽位推进完全看不到矩阵行列。

这是导入器的功能缺口，不是排版器问题。

### 2.4 其他转换损耗（P2）

- `\left( \frac{a}{b} \right)` 生成 `▸p ▸fa;b; ;`，括号内多出前导空格；
- 部分 `=` 两侧空格在往返后丢失（如 `dx;= ▸r` 反推为 `dx= \sqrt`）；
- `{e}` 的外层花括号被剥掉；对普通文本影响不大，但会改变分组语义；
- `\sqrt{x^2+y^2}` 这类简单指数能侥幸往返，但 AST 中仍是文本 `^`，不是 `▸u` 结构，导航看不到指数槽；
- `\mathrm{d}` 的薄间距依赖导出阶段补 `\,`，不是转换阶段生成的稳定语义。

## 3. 导入弹窗的交互问题

### 3.1 “校验反推 LaTeX”导致弹窗变形（P0）

代码：`src/modals.rs:365-373`。

```rust
let verified_latex = mathslot_core::latex::to_latex(&verified_parsed);
ui.horizontal(|ui| {
    ui.label(...);
    ui.label(RichText::new(&verified_latex).monospace().size(11.0).color(TEXT));
});
```

问题：

- `ui.horizontal` 不换行；
- `Label` 没有 `.wrap()` / `.truncate()`；
- `egui::Window` 只有 `default_width(720)` / `min_width(580)`，没有 `max_width`；
- 长 LaTeX 会撑宽窗口，导致弹窗尺寸跳变、按钮被挤走；
- 下方的简码结果也是 `TextEdit::singleline`，长文本同样会撑宽。

建议修复：

- 将校验结果放进 `CollapsingHeader` 或固定高度的 `ScrollArea`；
- 使用 `ui.add(egui::Label::new(...).wrap())`；
- 给窗口加 `.max_width(760.0)`；
- 代码框使用横向滚动或 `TextEdit::multiline`；
- 或者在超长时显示“展开查看”，默认只显示摘要。

### 3.2 不能直接把导入结果保存为模版（P1）

当前 LaTeX 导入页只有：

- `复制简码流`
- `✓ 替换当前编辑器内容`
- `+ 插入到当前光标处`

见 `src/modals.rs:380-410`。

没有“保存为片段模版”或“保存为自定义格式”。用户必须先插入编辑器，再回到主界面点“+ 存片段”，流程断裂。

建议增加：

- **“保存为片段模版 (t▸)”** 按钮：对 `latex_converted_mathslot` 调用 `UserLibrary::add_snippet_auto`（`library.rs:445`），然后 `save_library_to_disk`，刷新片段列表；
- 可选名称输入框（默认用 LaTeX 首段或“导入公式”）；
- 保存成功后反馈 `t<key>`，并保持弹窗打开；
- 如果转换结果为空或包含空槽，禁用保存并提示原因。

### 3.3 校验只展示，不判定有损（P1）

当前“校验反推”只是把 `to_latex(parse(code))` 打出来，没有：

- 与原 LaTeX 做归一化比较；
- 检测空槽（如 `▸s...;;`）；
- 标记 `▸` 指令外的原始 `^/_`；
- 在转换结果有疑点时禁用“替换/插入”。

建议增加一个 `ConversionReport`：

```rust
pub struct ConversionReport {
    pub could_roundtrip: bool,
    pub empty_slots: usize,
    pub raw_script_tokens: usize,
    pub unsupported_environments: Vec<String>,
    pub warnings: Vec<String>,
}
```

UI 对警告显示黄色提示，严重时禁用操作。

## 4. 设计层面的根因

### 4.1 `^` / `_` 的双重表示

MathSlot 已有结构化上下标：

- `▸u` 上标（底数; 指数）
- `▸d` 下标（主体; 下标）
- `▸b` 上下标（主体; 下标; 上标）

但解析器把文本里的 `^` / `_` 当普通文本，导出器再用 `latex_operand` 重新解释。导入器又输出原始 `^/_`，形成三套语义：

1. 结构化 `▸u/▸d/▸b`
2. 原始文本 `^/_`
3. 导出阶段的 `latex_operand` 启发式

这是上下标错误的根源。建议：

- **导入器优先输出 `▸u/▸d/▸b`**；
- 或者解析器把裸 `^/_` 提升为结构化上下标；
- 不要长期维持两套可写的表示。

### 4.2 导入器是字符串重写器，不是解析器

`convert_latex_chars` 用字符扫描 + 局部 `get_latex_arg`，适合 `\frac`、`\sqrt`、`\lim` 这种固定参数结构，但不适合：

- 上下标需要“先有原子，再有脚本”；
- 矩阵需要行/列/环境状态；
- 嵌套分组需要保留作用域；
- `\left...\right` 需要成对定界符状态。

建议把导入器升级为“轻量 LaTeX AST”：

```text
LatexNode
├── Text
├── Command { name, args }
├── Group { children }
├── Script { base, sub, sup }
├── Delimited { open, children, close }
└── Environment { name, rows: Vec<Vec<Vec<LatexNode>>> }
```

第一阶段不必完整实现 LaTeX，只需覆盖当前词表 + 脚本 + 矩阵环境。

### 4.3 校验预览与转换结果没有共享 AST

当前 UI 先 `latex_to_mathslot` 成字符串，又 `parse_with_library` 成 AST，再 `to_latex`。中间没有保存“转换损耗”的信息。建议转换 API 返回：

```rust
pub struct ConversionOutput {
    pub code: String,
    pub parsed: ParsedDoc,
    pub report: ConversionReport,
    pub roundtrip_latex: String,
}
```

UI 直接使用同一份 AST 做预览和校验，避免字符串二次解释。

## 6. 建议修复顺序

### P0（先修数据正确性和弹窗）

1. **精确关系宏匹配**：修 `extract_term_body`，把 `starts_with("\\le")` 改为完整宏名判断。
2. **上下标结构化**：导入器遇到 `^`/`_` 时，按“原子 + 脚本”生成 `▸u`/`▸d`/`▸b`；至少先保证 `e^{-x^{2}}`、`x^{a+b}`、`a_{i+1}`、`e^{-\frac{x}{2}}` 正确。
3. **弹窗防变形**：校验结果 wrap + `max_width`；简码结果横向滚动。
4. **转换结果校验**：检测空槽和疑似有损，至少对 `\left` 空槽给出警告。

### P1（导入体验）

5. 增加“保存为片段模版 (t▸)”按钮。
6. 支持矩阵环境或将不支持的 `\begin{...}` 明确标记为“未支持，不自动替换”。
7. 加入转换 round-trip 测试矩阵。
8. 在导入页显示“有损/空槽”提示，严重时禁用替换/插入。

### P2（长期）

9. 用轻量 LaTeX AST 替换 `convert_latex_chars` 的字符串重写。
10. 解析器统一支持裸 `^/_` 到结构化脚本的升级路径。
11. 统一桌面端/插件 keymap。
12. 更新 README 的 WASM 体积和导航文档。

## 7. 验收矩阵

| 输入 | 期望 |
| :--- | :--- |
| `e^{-x^{2}}` | 往返仍为 `e^{-x^{2}}`，不产生 `e^{-x}^{2}` |
| `x^{a+b}` | 指数完整保留 `a+b` |
| `a_{i+1}` | 下标完整保留 `i+1` |
| `e^{-\frac{x}{2}}` | 指数内保留整个分式 |
| `\sum_{i=1}^{n} \left( a_i \right)` | 求和主体槽非空，`\left(...\right)` 在主体内 |
| `\int_a^b \left( f(x) \right) dx` | 积分主体槽非空 |
| `\begin{pmatrix} a & b \\ c & d \end{pmatrix}` | 生成矩阵结构，`&` 不被转义 |
| 长 LaTeX | 弹窗宽度不跳变，校验结果可滚动/换行 |
| 导入结果保存 | 可直接生成 `t▸` 片段并在主界面复用 |

建议把这些用例同时加入：

- `crates/mathslot-core` 的 Rust 单元测试；
- `obsidian-mathslot/scripts/build.mjs` 的 WASM smoke test；
- 桌面端导入弹窗的 UI 回归截图。
