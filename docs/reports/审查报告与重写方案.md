## 0. 结论摘要

### 0.1 一句话评价

MathSlot 把“写公式”设计成了一套高效的流式简码输入法，这个方向是成立的；但当前版本更像一个功能很多、验证很勤的原型，而不是一个可以让用户放心存放公式和自定义库的成熟产品。**最大的风险不是功能少，而是用户会在没有提示的情况下得到错误结果或丢失数据。**

### 0.2 分项判断

评分是审查者的主观判断，仅用于排序，不是精确指标。

| 维度 | 判断 | 说明 |
|---|---|---|
| 产品方向 | A | 流式简码、免鼠标、槽位导航，和传统 LaTeX 输入有明确差异 |
| 交互创新 | A- | 单字母直达、Tab 前缀、分号推进、层级导航都很有想法 |
| 核心正确性 | C+ | 调色板与文档存在错码；非法节点在输出时被静默丢弃 |
| 工程质量 | C | 核心文件过大，双解析器/双 AST，UI 与领域逻辑耦合 |
| 数据安全 | C- | 配置损坏静默回退；多处保存错误被忽略；公式 ID 可能碰撞 |
| 跨端一致性 | C | 共享 core，但桌面端与 Obsidian 的功能集、渲染、主题差异明显 |
| 文档一致性 | D | README/HELP 中多处简码与实际命令目录不一致 |
| 可测试性 | B- | 有 133 个测试且全部通过，但缺 UI/数据一致性测试，CI 不跑测试 |
| 重写必要性 | 高 | 但应分阶段，先修 P1，再替换架构，不宜一次性重写全部 |

### 0.3 最需要先处理的五件事

1. **调色板 5 张卡片插入了错误命令**：例如“偏导”实际插入 `\to`，“叉乘”实际插入 `\nabla`。这是核心功能错误，不是文案问题。
2. **复制/导出的 LaTeX 会静默丢弃非法或未完成的节点**：预览里还能看到红色 `?` 或琥珀色 Pending 徽章，复制出来却直接消失。
3. **配置读取失败会静默回退默认库，保存失败在多处被 `let _ =` 忽略**：用户可能以为已保存，实际没有。
4. **文档中的简码与命令目录大面积漂移**：`▸ch`、`▸ci/cj`、`▸op/oq`、`▸qm` 等都有问题；照文档输入会得到错误命令。
5. **桌面端和 Obsidian 端各自维护一套 UI 胶水，核心又存在两套解析/渲染栈**：继续叠加功能会让分叉越来越大。

## 2. 项目现状

### 2.1 产品定位

MathSlot 是一个“书写流优先”的数学公式编辑器：

- 用户输入简码流，而不是逐字写 LaTeX；
- `Tab` 进入结构前缀，单字母直达常用结构；
- 分号 `;` 推进槽位；
- 支持嵌套结构、槽位导航、跳转历史；
- 输出标准 LaTeX，桌面端用 `latex-rust` 预览，Obsidian 端用 MathJax 预览；
- 支持 LaTeX 反向导入、自定义格式、片段模版、88 条预置公式。

### 2.2 实际架构（as-built）

README 描述的分层在依赖关系上成立，但**运行时主路径绕过了 Session 门面**：

```text
┌──────────────────────────┐        ┌──────────────────────────┐
│ Desktop (egui/eframe)    │        │ Obsidian plugin (JS)     │
│ src/app.rs               │        │ src/plugin.js            │
│ src/modals.rs            │        │ + inline base64 WASM     │
└────────────┬─────────────┘        └────────────┬─────────────┘
             │                                   │
             └──────────────┬────────────────────┘
                            ▼
          mathslot-core: editor / parser / ast / command
                         latex / visual / library
                            │
             ┌──────────────┴──────────────┐
             ▼                             ▼
   mathslot-syntax / doc / latex     mathslot-wasm (C ABI)
   （Session 的底层；测试覆盖）        （Obsidian 使用）
   （桌面/WASM 运行时基本不用）
```

关键事实：

- 桌面端和 WASM 都直接 `use mathslot_core::{ast, parser, latex, editor, visual}`；
- `mathslot-core::session::Session` 只在测试和 `lib.rs` re-export 中出现，两个实际前端都没有使用；
- `mathslot-syntax` / `mathslot-doc` / `mathslot-latex` 是另一套更“干净”的解析/文档/导入栈，但没有成为运行时主路径；
- 因此项目里同时存在**两套 AST、两套解析器、两套 LaTeX 生成/导入逻辑**。

这不是简单的“分层”，而是“两条产品线”。任何解析或渲染修复都必须在两处判断是否需要同步，长期一定会分叉。

### 2.3 数据流

以桌面端一次击键为例：

```text
TextEdit 输入
  → StreamEditor::sync_after_edit
  → parser::parse_with_library
  → visual::build_preview_latex / build_nav_latex
  → RenderWorker（后台线程，latex-rust）
  → PNG → egui Texture
  → 预览框 / 导航框
```

输出路径：

```text
StreamEditor.parsed
  → core::latex::to_latex
  → formatted_latex（加 $ / $$ / code fence）
  → 系统剪贴板
```

导入路径：

```text
LaTeX 文本
  → core::latex::latex_to_mathslot（启发式字符串扫描）
  → 简码流
  → 再 parse / to_latex 做“校验反推”
```

## 3. 功能设计评估

### 3.1 做得好的地方

1. **流式输入模型是真正的差异化。** 不是把 LaTeX 编辑器换个皮肤，而是重新设计了“人如何想公式、手如何按键”的映射。
2. **单字母直达 + 二级子菜单 + 分号推进**的组合效率很高，熟练后可以完全脱离鼠标。
3. **嵌套槽位导航和面包屑**是亮点：`Esc`/`Tab j` 进入后按字母跳转，配合跳转历史，解决了“公式越长越难改”的问题。
4. **预览中的绿色活动槽位、红色空槽、紫色子式徽章**，把内部结构可视化了，这是很好的教学和纠错设计。
5. **LaTeX 反向导入、自定义格式、片段模版、88 条预置公式**，说明产品不是只做“输入”，而是想覆盖“积累和复用”。
6. **核心有 133 个测试**，且覆盖了不少真实公式、嵌套结构、导航和导入场景，这在同类小项目里很少见。

### 3.2 核心设计矛盾

#### 矛盾一：隐式模式与标准文本编辑冲突

当前编辑器同时承担：

- 普通文本输入；
- `▸` 命令前缀；
- `Tab` 进入前缀菜单；
- `;` 槽位推进；
- `Esc` 导航模式；
- 智能前置包裹；
- 内联 `▸j...` 跳转；
- 括号自动配对；
- 自定义快捷键。

这些状态大多不是显式的状态机，而是由 `source` 与光标的局部形状、以及编辑前后的 diff 推断出来的。结果是：

- 用户很难预测“我现在是在输入文本，还是在输入命令”；
- 粘贴一段包含 `▸` 的文本，可能被当成命令解释；
- 智能包裹在粘贴、删除、快速输入时可能误触发；
- 撤销的粒度由 450ms 时间窗和字符差决定，而不是由用户意图决定。

这不是某个函数的 bug，而是**交互模型缺少显式状态和事务边界**。

#### 矛盾二：没有单一事实源

同一个“命令”至少出现在五个地方：

1. `command.rs` 的 `DIRECT_ENTRIES` / `SYMBOL_ENTRIES` / 各子菜单常量；
2. `app.rs` 的调色板硬编码卡片；
3. `HELP.md` 的手写表格；
4. `README.md` 的手写宣传/速查；
5. `obsidian-mathslot` 的 catalog JSON / UI。

只要其中一处改了，其他几处就可能漂移。当前已经漂移，而且不是一两处。

#### 矛盾三：两套核心栈

`mathslot-syntax` / `mathslot-doc` / `mathslot-latex` 的设计更接近“正确”的工程分层：

- `mathslot-syntax`：lexer、parser、AST、diagnostics、printer；
- `mathslot-doc`：Document、Transaction、UndoStack、SlotTable；
- `mathslot-latex`：LaTeX 导入、环境识别、round-trip 验证、ImportReport。

但桌面端和 WASM 实际用的是 `mathslot-core` 里另一套：

- `core::parser`：流式简码解析，带 library/custom format；
- `core::ast`：另一套 AST；
- `core::latex`：另一套 LaTeX 生成和启发式导入；
- `core::editor::StreamEditor`：自己的撤销快照。

结果：

- `Session` 事务模型没有被真实前端使用；
- 导入页用的是 `core::latex::latex_to_mathslot`，而不是更完整的 `mathslot-latex::convert_latex_with_report`；
- `mathslot-syntax` 的 diagnostics 没有进入桌面端 UI；
- 两套逻辑的边界和语义会越来越难对齐。

#### 矛盾四：图像渲染与“可编辑的数学”不匹配

预览和导航都是 `latex-rust` 渲染出的 PNG：

- 无法选中、复制、屏幕阅读器读取；
- 布局完全由 Rust 代码计算，宽度/高度适配容易出错；
- 导航图不是可交互控件，只是一个 bitmap；
- 主题、DPI、缩放都要自己处理；
- 渲染失败时只能整体降级，无法定位到具体节点。

这对“公式预览”可以接受，但对“导航结构图”和“可访问性”就不太合适。

#### 矛盾五：UI、领域、持久化耦合

- `app.rs` 2520 行，既管 UI，又管编辑、撤销、焦点、调色板、渲染调度；
- `modals.rs` 1607 行，既管界面，又管 `library.json` 的路径、读写、备份；
- WASM 端又把同样的状态和命令胶水用 C ABI 重写了一遍。

这导致：

- 领域逻辑无法在无 UI 环境下完整测试；
- 桌面端和 Obsidian 端的行为容易分叉；
- 换 UI 框架（例如从 egui 换到 Web）成本极高。

#### 矛盾六：渲染性能模型偏粗

`app.rs` 每次 `render_dirty` 都提交一个 `RenderJob`；worker 会把队列中更新的 job 合并，但**一旦开始渲染就无法取消**，并且每个 job 都同时渲染 preview 和 nav：

```rust
let preview = renderer.render_doc(..., Mode::Preview);
let nav = renderer.render_doc(..., Mode::Nav);
```

没有按内容哈希缓存，没有 debounce，没有“只渲染可见部分”。复杂公式连续输入时，用户会看到预览落后于输入。

### 3.3 交互走查

| 场景 | 当前体验 | 问题 |
|---|---|---|
| 输入短公式 | 流畅，预览即时 | 正常 |
| 点击调色板“偏导” | 插入 `▸ob` | 实际是 `\to`，不是 `\partial` |
| 输入很长的公式 | 预览被居中裁切，两端都看不到 | 见 `02-long-formula-clipped.png` |
| 3×3 矩阵导航 | 导航图超出固定高度区域 | 见 `03-matrix-nav-overflow.png` |
| 按文档输入 `▸ch` | 无此命令 | 文档写错，应为 `▸ci` |
| 按文档输入 `▸qm` | 插入 `\setminus` | 文档想表达 `\mathbb{C}`，实际是 `▸qn` |
| 输入半截 `▸m` 后复制 | 复制结果里没有这个节点 | `to_latex` 对 Pending/Unknown 返回空串 |
| 配置文件损坏 | 静默回退默认库 | 没有阻断式提示，下一次保存覆盖主文件 |
| 删除一个公式 | 立即删除 | 没有确认，也没有撤销 |

## 4. 缺陷与不足

> 标记说明：`[已验证]` 表示通过代码、测试或截图确认；`[风险]` 表示是结构上很可能发生、但未做完整运行时验证的问题。

### 4.1 P1：必须优先修复

#### P1-1 调色板 5 张卡片的简码与语义错位 `[已验证]`

`app.rs` 的 `common_symbols` 是硬编码的，卡片显示和实际插入的 code 不一致：

| 卡片 | 显示 | 实际 code | 实际 LaTeX | 正确 code |
|---|---|---|---|---|
| `ob` | 偏导 `∂` | `ob` | `\to` | `oc` |
| `od` | 叉乘 `×` | `od` | `\nabla` | `of` |
| `oe` | 点乘 `·` | `oe` | `\pm` | `og` |
| `xa` | 约等于 `≈` | `xa` | `\equiv` | `xb` |
| `xb` | 恒等于 `≡` | `xb` | `\approx` | `xa` |

![调色板与预览：偏导、叉乘、点乘、约等于、恒等于等卡片](docs/assets/01-palette-and-preview.png)

证据：

- `/home/mat/Projects/mathslot/app.rs:1496-1505`
- `/home/mat/Projects/mathslot-next/crates/mathslot-core/src/command.rs:1151-1200`（`ob`=To, `oc`=Partial, `od`=Nabla, `oe`=Pm, `of`=Times, `og`=Cdot）
- `/home/mat/Projects/mathslot-next/crates/mathslot-core/src/command.rs:583-600`（`xa`=Equiv, `xb`=Approx）

影响：

- 用户点击“偏导”得到箭头，点击“叉乘”得到梯度；
- hover 文案也在教错误的快捷键；
- 这是主功能错误，不是视觉文案问题。

修复：

- 不要硬编码；从 `SYMBOL_ENTRIES` / `RELATION_ENTRIES` 生成 `common_symbols`；
- 或者建立 `tile(code)` 构造函数，从 catalog 取 label/glyph；
- 增加测试：每个 tile 的 `code` 解析后必须与 `label`/`glyph` 对应。

#### P1-2 文档/帮助与命令目录大面积漂移 `[已验证]`

| 文档写法 | 位置 | 实际 |
|---|---|---|
| `▸ch` 全导分式 | README:42、HELP:142、HELP:395 | 不存在；实际是 `▸ci` |
| `▸ci` 上大括号、`▸cj` 下大括号 | README:42、HELP:143-144 | 实际是 `▸aj` / `▸ak`；`ci` 是全导分式 |
| `▸op` 平行 | README:43、HELP:182 | `op` 是垂直；平行是 `▸oo` |
| `▸oq` 垂直 | README:43、HELP:183 | 不存在；垂直是 `▸op` |
| `▸qm` 复数集 | README:43、HELP:195 | `qm` 是集合差；复数集是 `▸qn` |

影响：

- 用户照文档输入，得到错误命令或未知命令；
- `▸qm` 会插入 `\setminus`，不是 `\mathbb{C}`；
- 文档越详细，误导越大。

修复：

- 以命令目录为唯一事实源，构建时生成 HELP 表格、README 速查、调色板数据和 TypeScript 类型；
- CI 增加“文档覆盖测试”：每个命令必须出现在生成的文档中，文档中的每个 code 必须能解析；
- 在命令目录变更时，禁止手改生成文件。

#### P1-3 长公式预览被居中裁切 `[已验证]`

证据：

- `/home/mat/Projects/mathslot/app.rs:944-966`
- `ScrollArea::both()` 内部用 `ui.vertical_centered` 加 `fit_to_exact_size(display_size)`

## 6. 从零重写方案

> 前提：这不是“把现有代码换个框架”。重写的目标是**把命令语言、编辑语义、渲染、持久化拆成可独立验证的层**，并让桌面端与 Obsidian 共享同一套核心和尽量多的 UI。

### 6.1 目标与非目标

**目标**

1. **正确性优先**：任何输入都不静默丢失；任何输出都可解释。
2. **单一事实源**：命令目录、解析器、AST、文档、调色板只保留一套。
3. **标准编辑体验**：选区、剪贴板、IME、撤销、多行、无障碍。
4. **跨端一致**：桌面端与 Obsidian 共享核心、共享 UI 组件、共享渲染。
5. **可测试**：领域逻辑可在无 UI、无渲染、无文件系统的环境下测试。
6. **数据安全**：崩溃/断电/损坏/并发写都不会静默丢用户数据。
7. **性能可度量**：解析、渲染、启动、内存都有预算和 benchmark。

**非目标（v1 不做）**

- 完整支持所有 LaTeX 宏包；
- 云端同步/协作；
- AI 公式生成；
- 插件市场/主题市场；
- 一次重写就支持所有平台的所有输入法。

### 6.2 架构原则

1. **一个语法，一棵 AST。** 不允许再有第二套 parser。
2. **不完整输入是常态。** `▸f`、`▸f a;` 必须是一等公民，而不是错误。
3. **诊断是一等数据。** 每个节点有 span，每个错误有 code/hint。
4. **编辑是事务。** 每个用户意图产生一个可逆 transaction。
5. **UI 与领域分离。** app-core 不依赖 egui、DOM、Obsidian。
6. **持久化只存用户数据。** 内置内容编译期加载，按稳定 ID 合并。
7. **渲染是后端。** 桌面/Obsidian 可以换 MathJax/KaTeX/latex-rust，但语义一致。
8. **元数据生成。** 调色板、帮助、README 表格、TS 类型都从 catalog 生成。
9. **标准编辑原语优先。** 不要重新实现光标、选区、IME、剪贴板。
10. **先测量，再优化。** 每个阶段有 benchmark 和验收指标。

### 6.5 关键数据模型

```rust
/// 字节偏移，避免 Rust/JS 的 char/UTF-16 下标混用。
pub struct Span { pub start: u32, pub end: u32 }

pub struct Diagnostic {
    pub severity: Severity, // Error | Warning | Info
    pub code: &'static str,
    pub span: Span,
    pub message: String,
    pub hint: Option<String>,
}

pub struct CommandSpec {
    pub id: CommandId,              // 稳定 ID，例如 "frac"
    pub keys: &'static [KeySeq],    // 例如 ["f"] 或 ["c", "a"]
    pub label: &'static str,
    pub category: Category,
    pub glyph: &'static str,
    pub slots: &'static [SlotRole],
    pub latex: LatexTemplate,       // 例如 "\\frac{$1}{$2}"
    pub doc: &'static str,
    pub examples: &'static [&'static str],
}

pub struct Document {
    pub source: String,
    pub ast: Ast,
    pub slots: SlotTable,
    pub diagnostics: Vec<Diagnostic>,
}

pub struct Transaction {
    pub edits: Vec<Edit>,
    pub selection_before: Selection,
    pub selection_after: Selection,
    pub intent: Intent,             // Typing | Command | Paste | Delete | Import | ...
}

pub enum Effect {
    Render(RenderRequest),
    Persist(SaveRequest),
    Clipboard(String),
    Status(Status),
}
```

关键点：

- **Span 用字节偏移**；只在 WASM/JS 边界做 UTF-16 转换。
- **`Document` 永远带 diagnostics**；UI 不自己猜错误。
- **`Transaction` 带 intent**；撤销合并只看 intent，不看时间。
- **`Effect` 是副作用清单**；app-core 不直接渲染/写文件/弹窗，便于测试。

### 6.6 解析与命令目录

#### 解析器

- 手写 lexer + 递归下降/Pratt parser，不引入重型 parser generator；
- 支持不完整输入：`Pending`、`MissingSlot`、`Invalid` 都是一等节点；
- 每个节点有 `Span`；
- 深度/节点数超限返回 `Diagnostic`，不返回 `"?"`；
- 解析器接受 `CommandCatalog`，自定义格式/片段也走同一套节点；
- 增量解析可选：先用全量解析 + 缓存，文档很大时再上 `rowan`/增量。

#### 命令目录

建议用 `catalog/commands.toml` 作为唯一事实源：

```toml
[[commands]]
id = "frac"
keys = ["f"]
label = "分数"
category = "structure"
glyph = "a/b"
slots = ["num", "den"]
latex = "\\frac{$1}{$2}"
doc = "插入分数，分子在前，分母在后。"
examples = ["▸f1;2;"]
```

构建时生成：

- `mathslot-command/src/generated.rs`（`&'static [CommandSpec]`）；
- `catalog.json`（给 WASM/TS/Obsidian）；
- `docs/commands.md` / HELP 表格；
- `packages/ui/src/generated/catalog.ts`；
- `schemas/commands.schema.json`。

CI 测试：

- 键序列唯一；
- 每个 `CommandSpec` 有 label/doc/example；
- 调色板每个 tile 的 code 都能解析到对应命令；
- 文档中出现的每个 `▸xx` 都能解析；
- 每个命令至少有一个 golden 测试。

这一步能直接消灭 P1-1、P1-2 和大量未来漂移。

### 6.7 编辑与撤销

- 每个用户动作生成一个 `Transaction`：
  - 输入一个字符：`Intent::Typing`，可在同一输入串内合并；
  - 点击卡片/命令：`Intent::Command`，单独一步；
  - 粘贴/导入/删除：各自单独一步；
  - 导航跳转：不改文本，不改 undo。
- `History` 存逆操作，不存整段源码快照（公式很小，先 String 也可以；文档变大再换 rope）。
- 智能包裹改为**显式建议**：检测到前置原子时，在 UI 显示 ghost 预览，用户按 Tab/Enter 接受；不接受就不改源码。不要用 diff 猜。
- 括号配对、选区包裹、缩进等文本操作使用标准编辑原语；光标默认停在括号内。
- 所有编辑操作都有 headless 测试：给定 source/selection/命令，断言新 source/selection/diagnostics/undo 深度。

### 6.8 渲染

```rust
pub trait MathRenderer {
    fn render(&self, req: &RenderRequest) -> Result<RenderOutput, RenderError>;
}

pub struct RenderRequest {
    pub id: RenderId,
    pub latex: String,
    pub theme: Theme,
    pub scale: f32,
    pub format: RenderFormat, // Svg | Png
}

pub struct RenderOutput {
    pub id: RenderId,
    pub output: RenderData,
    pub degraded: bool,
    pub diagnostics: Vec<Diagnostic>,
}
```

策略：

- **桌面与 Obsidian 主渲染统一用 MathJax 3 SVG**，保证 WYSIWYG 一致、可访问、可选中；
- `latex-rust` 只作为可选的原生后端/离线后备；
- 失败时返回 `degraded + diagnostics`，UI 明确显示；
- 缓存 key = hash(latex, theme, scale, backend)；
- 渲染请求带 generation，新的请求取消旧的；
- 预览默认 fit-to-width，提供“实际大小”；
- 导出 SVG/PNG 文件，而不是只复制 LaTeX；
- 对自定义宏做支持性检查，给出“可能在目标环境不可渲染”的警告。

### 6.9 持久化与数据安全

配置只存用户数据：

```rust
#[derive(Serialize, Deserialize)]
pub struct LibraryFile {
    pub schema_version: u32,
    pub custom_formats: Vec<CustomFormat>,
    pub snippets: Vec<Snippet>,
    pub user_formulas: Vec<UserFormula>,
    pub settings: Settings,
}
```

规则：

- 内置预置从 `presets.json` 编译期加载，按稳定 ID 合并；用户修改存 override；
- 平台路径用 `directories::ProjectDirs`：Linux XDG、macOS `Application Support`、Windows `Roaming`；
- 保存：同目录 `tempfile` → `write_all` → `sync_all` → `persist`（原子替换）→ `fsync(dir)`；
- 备份：保留 N 代带时间戳的 `.bak`；
- 损坏：重命名为 `library.corrupt-<timestamp>.json`，尝试备份，主界面显示恢复向导，绝不静默覆盖；
- 并发：文件锁；
- 导入：先全部校验，再一次性提交；失败回滚；
- 测试：kill -9、磁盘满、权限拒绝、损坏 JSON、并发写、跨平台路径。

### 6.10 前端与交互

#### 编辑器

推荐 **CodeMirror 6**：

- 原生选区、剪贴板、IME、移动端、屏幕阅读器；
- `Decoration` 高亮 `▸` 命令、活动槽位、错误节点；
- `keymap` 处理 Tab/Enter/`;`/Esc，不劫持标准编辑快捷键；
- Obsidian 本身基于 CodeMirror 6，集成自然；
- 桌面 Tauri 和 Obsidian 共用同一套扩展。

#### 布局

- 左侧：输入 + 调色板/命令搜索；
- 右侧：预览 + 结构化导航；
- 底部：诊断/状态；
- 设置页：主题、快捷键、分隔符、渲染后端、配置路径、导入/导出。

#### 交互原则

- 默认聚焦输入，但 Tab 可以离开；
- 所有快捷键可配置，避免占用系统保留组合；
- 危险操作（删除/覆盖/导入）有确认或撤销；
- 错误可见、可定位、可复制；
- 明暗主题跟随宿主；
- 键盘-only 可完成所有核心操作；
- 断网/渲染失败时仍能编辑和复制 LaTeX。

### 6.11 WASM 与 Obsidian

- 用 `wasm-bindgen` 暴露少量类型化 API：

```rust
#[wasm_bindgen]
pub struct Engine { /* ... */ }

#[wasm_bindgen]
impl Engine {
    #[wasm_bindgen(constructor)]
    pub fn new(catalog_json: &str) -> Engine;
    pub fn dispatch(&mut self, event_json: &str) -> String;
    pub fn snapshot(&self) -> String;
    pub fn engine_version(&self) -> String;
}
```

- 用 `serde-wasm-bindgen` 或 JSON 传输，TS 端有生成类型；
- `wasm-opt -Oz`，外部 `.wasm` + 懒加载；如果 Obsidian 分发必须单文件，再内联压缩版；
- 版本握手：UI 与 core 不匹配时提示升级，而不是崩溃；
- Obsidian 插件：
  - 共享 `packages/ui`；
  - 使用 Obsidian CSS 变量；
  - 设置页：分隔符、主题、快捷键、库导入导出；
  - 代码块处理器/阅读视图渲染；
  - 移动端真机测试；
  - 损坏库备份/恢复。

### 6.12 技术栈

| 层 | 推荐 | 理由 | 备选 |
|---|---|---|---|
| 核心语言 | Rust 2024 | 现有核心可复用，性能/安全/跨端 | Rust 2021 |
| 序列化 | `serde` + `serde_json` + `schemars` | 替换手写 JSON，生成 schema | `serde_yaml`（仅配置） |
| 错误 | `thiserror` + `tracing` | 结构化错误/日志 | `anyhow`（仅应用层） |
| ID | `uuid` v7 | 时间有序、无碰撞 | ULID |
| 解析 | 手写递归下降 + 可选 `rowan` | 流式/不完整输入可控 | `chumsky`、`logos` |
| 桌面 | Tauri 2 + Svelte 5 + Vite | 共享 Web UI、CodeMirror、MathJax、无障碍 | egui 0.37 + latex-rust |
| 编辑器 | CodeMirror 6 | 选区/IME/移动端/装饰/键盘 | Monaco（太重） |
| 渲染 | MathJax 3 SVG | 与 Obsidian 一致、可访问、覆盖广 | KaTeX（快但覆盖少）、latex-rust（原生） |
| Obsidian | TypeScript + esbuild + Obsidian API | 官方生态、CM6 同源 | 现有 vanilla JS |
| WASM | `wasm-bindgen` + `serde-wasm-bindgen` + `wasm-opt` | 类型安全、少手工 ABI | 手写 C ABI |
| 存储 | `directories` + `tempfile` + `fs2` | 跨平台路径/原子写/锁 | 自写 |
| 测试 | `cargo-nextest`、`insta`、`proptest`、`criterion` | 单测/快照/属性/基准 | `rstest` |
| 前端测试 | Vitest + Playwright | 组件/E2E/截图 | Cypress |
| CI | GitHub Actions 三平台矩阵 | 现有发布流可复用 | GitLab CI |

#### 为什么推荐 Tauri，而不是继续 egui

- 当前大量 UI 问题（单行换行、选区、焦点、无障碍、IME）本质上是**在即时模式 UI 里重新实现文本编辑器**。这不是 egui 的强项。
- CodeMirror 6 已经解决了这些问题，并且 Obsidian 本身就用它。
- Tauri 用系统 WebView，比 Electron 轻；桌面与 Obsidian 可以共享 UI 组件和 MathJax 渲染。
- 代价是 Linux 需要 WebKitGTK，启动/内存与 egui 不同；这会放弃 README 里“零 WebKit 依赖”的卖点。

**如果“零 WebKit/最小原生”是硬约束**：保留 egui 桌面端，但仍然建议：
- 抽出 `mathslot-app` 状态机；
- 桌面端只做 shell；
- Obsidian 端共享 Rust core + catalog，但不强行共享 UI；
- 用 `egui` 的 TextEdit 增强或嵌入轻量编辑器，明确单行/多行语义。
这样架构仍然比现在清晰，但双端 UI 分叉会保留。

### 6.15 迁移计划（Gate DAG）

迁移不按时间排期，而按依赖门禁推进。每个 Gate 的退出条件全部满足后才能进入下一个；任务 ID、依赖与验收见 `LLM_IMPLEMENTATION_SPEC.md` §14。

| Gate | 目标 | 交付 | 退出条件 |
|---|---|---|---|
| G0 基线与护栏 | 让现状可验证、可回退 | CI（fmt/clippy/test/WASM/plugin）；P1 失败回归测试；故障注入 harness；基线 tag | CI 绿；P1 测试存在；clippy 债务受控；基线建立 |
| G1 单一事实源 | 消灭双解析器/双命令表 | catalog + 生成器；选定唯一 parser/AST；流式语义移植；诊断贯通；新旧双跑 | 运行时只有一个 parser/AST；调色板/文档由 catalog 生成；诊断可见可导出 |
| G2 app-core 与数据层 | 领域逻辑与 UI/IO 解耦 | 状态机；事务撤销；store（原子写/备份/锁/迁移）；render（缓存/取消/降级/fit）；headless parity | app-core 可独立测试；A-DATA/A-RENDER 验收通过 |
| G3 UI 与双端 | 替换自绘输入，统一桌面/Obsidian | CodeMirror 6；调色板/导航；预览/诊断；设置/主题；Tauri 壳；Obsidian 壳 | 桌面与 Obsidian E2E；核心功能清单对齐 |
| G4 硬化与发布 | 收口质量与发布 | 导入诊断/diff；故障注入全量；性能基准；a11y 审计；生成文档；发布流水线 | P1/P2 清零；验收全过；发布可回滚 |

**迁移策略**

- 用现有 133 个测试作为 characterization baseline；
- 新旧实现双跑：同一输入，比较简码/AST/LaTeX/诊断；
- 先替换“读路径”（parse/render），再替换“写路径”（edit/undo）；
- 每个 Gate 保留 feature flag，可回退；
- 不在迁移期间同时改命令语言；命令语言变更单独版本化；
- 任一验收不通过时停留在当前 Gate，不靠延期进入下一阶段。

### 6.16 风险与对策

| 风险 | 概率/影响 | 对策 |
|---|---|---|
| 编辑语义回归 | 高/高 | characterization tests + 新旧双跑 + 分阶段切换 |
| Tauri/WebView 改变产品定位 | 中/高 | 先做技术决策；保留 egui 备选；测启动/内存/包体 |

| 命令语言兼容性 | 高/高 | 保留旧 code 解析；catalog 版本化；迁移测试 |
| Obsidian API/移动端限制 | 中/中 | 早期原型；真机测试；剪贴板/文件 API 兜底 |
| 范围蔓延 | 高/高 | 阶段门禁；v1 非目标写死；每阶段可发布 |
| 数据迁移丢失 | 中/高 | 只读旧格式、先备份、迁移 dry-run、回滚 |
| 双端 UI 共享成本 | 中/中 | 先共享 core/catalog；UI 组件按需共享，不强行 100% |

### 6.17 验收标准

**正确性**

- 所有命令在 catalog 中有唯一键、标签、文档、示例；
- 调色板/HELP/README 100% 由 catalog 生成，CI 无 diff；
- 复制/导出永静默丢弃节点；有 Error 时阻止或显式提示；
- 支持的 LaTeX 子集 round-trip 归一化等价；
- 撤销/重做确定性测试通过。

**数据安全**

- 保存中断、磁盘满、权限拒绝、损坏 JSON、并发写测试通过；
- 损坏配置隔离并可恢复；
- 用户数据只存用户数据，内置预置可合并升级。

**体验**

- 长公式默认完整可见（fit-to-width）；
- 导航图不溢出、可键盘操作；
- 输入框支持多行/IME/标准选区；
- 所有核心操作可键盘完成；
- 明暗主题跟随宿主；
- 错误可定位、可复制、可恢复。

**性能**

- 典型公式解析 < 5ms、渲染 p95 < 100ms（目标，按实测调整）；
- 连续输入时预览延迟 < 100ms；
- 启动时间/内存有预算和 benchmark；
- WASM 体积有预算，移动端可接受。

**工程质量**

- 三平台 CI 绿：fmt、clippy、test、WASM build、插件 build、E2E；
- 无 P1/P2 未关闭；
- 架构文档与实际模块一致；
- 新贡献者按 README/脚本即可跑通开发、测试与构建。

## 7. 建议的实施顺序

> 本节是面向人类的摘要。权威任务表、依赖关系与完成定义见 `LLM_IMPLEMENTATION_SPEC.md` §14、§15；进度以 Gate 退出条件衡量，不以时间衡量。

### 7.1 Gate G0：让现状可验证

1. 加 CI：fmt/clippy/test/WASM/plugin。
2. 为 P1 缺陷补会先失败的回归测试。
3. 建故障注入 harness（损坏/只读/磁盘满/并发）。
4. 冻结命令语言，打基线 tag。

退出：CI 绿；P1 测试存在；clippy 债务受控。

### 7.2 Gate G1：单一事实源

1. 建 `catalog/commands.toml` 与生成器，生成调色板/文档/TS 类型。
2. 用 catalog 修 5 张卡片与文档漂移。
3. 选定一套 parser/AST，冻结另一套。
4. 把流式编辑语义移植到选定栈，贯通诊断。
5. 新旧双跑，确认核心输入/导航/复制一致。

退出：运行时只有一个 parser/AST；文档/调色板由 catalog 生成；诊断可见。

### 7.3 Gate G2：app-core 与数据层

1. 实现无 UI/IO 依赖的状态机。
2. 按 Intent 分组事务撤销。
3. 实现原子写、备份轮转、文件锁、schema 迁移。
4. 实现渲染缓存/取消/降级/fit。
5. headless parity：旧实现 vs app-core。

退出：app-core 可独立测试；数据/渲染验收通过。

### 7.4 Gate G3：UI 与双端

1. CodeMirror 6 编辑器 + 命令装饰/槽位。
2. 调色板/搜索/导航树。
3. 预览/诊断/错误折叠。
4. 设置/主题/快捷键。
5. Tauri 桌面壳与 Obsidian 壳共享 UI/core。
6. 双端功能清单对齐。

退出：桌面/Obsidian E2E 通过；无 singleline 伪多行。

### 7.5 Gate G4：硬化与发布

1. LaTeX 导入诊断/diff/round-trip。
2. 数据故障注入全量。
3. 性能基准与预算。
4. 无障碍审计。
5. 生成文档/README/HELP。
6. 发布流水线，旧版进入维护模式。

退出：P1/P2 清零；验收全过；发布可回滚。

## 8. 最终结论

MathSlot 的产品方向是成立的：它确实提供了一种比逐字写 LaTeX 更接近“书写”的输入方式，槽位导航和层级预览也解决了真实痛点。当前版本的测试数量和执行程度说明团队并不是在“随便做做”。

但工程上，它已经出现了一个典型信号：**功能增长快于事实源和边界建设**。调色板错码、文档漂移、复制静默丢节点、配置静默回退、秒级 ID 碰撞，这些问题单独看都不大，合在一起会让用户无法信任“我写的就是我得到的”。

因此建议：

- **不要直接推倒重来。** 先在 Gate G0 修 P1，把现有行为用测试固定下来。
- **然后在 Gate G1 做“单一事实源”重构**：catalog、parser、AST、文档、调色板只保留一套。
- **接着在 Gate G2–G3 做 UI/状态机重写**：用 CodeMirror/标准编辑原语替换自绘输入，用 app-core 隔离领域逻辑，并统一桌面与 Obsidian 的 UI/渲染。

如果只能做一件事：**让命令目录成为唯一事实源，并修掉调色板和文档的错码。**  
如果只能做两件事：**再加上配置/输出的数据安全。**  
如果只能做三件事：**再加上真正的文本编辑器，别再和 singleline/自绘光标搏斗。**
